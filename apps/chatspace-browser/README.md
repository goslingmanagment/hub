# Постоянная вкладка ChatSpace на сервере

С 2026-11-01 OnlyFans-данные хаба приходят только из ChatSpace (`chat.onlymonster.ai`): расширение ChatGoose
передаёт в хаб то, что ChatSpace уже получил, в первую очередь его сокет (каждое сообщение всех чатов, покупки PPV,
чаевые). Сокет есть, только пока открыта вкладка ChatSpace с аккаунтами. Этот контейнер держит такую вкладку
круглые сутки на `agency-de`, чтобы лента не прерывалась ночью.

## Как устроено

- Firefox ESR из репозитория Mozilla и наше расширение. Расширение ставит политика Firefox (`firefox/policies.json`)
  из фида обновлений (`https://ext.gosling-agency.ru/chat-extension/firefox/updates.json`) и дальше обновляет само,
  раз в час. Код захвата тот же, что у чаттеров.
- Политика сообщает расширению, что это серверная вкладка: `browser.storage.managed` → `{ serverTab: true }`.
- KasmVNC: X-сервер Firefox и экран для владельца (как у браузеров страниц), s6-overlay запускает службы, matchbox
  держит окно развёрнутым.
- Профиль на томе `csb-profile`: вход в OnlyMonster, вход расширения в хаб и открытые аккаунты ChatSpace (его
  localStorage) переживают перезапуск Firefox и пересоздание контейнера.
- Каждый запуск открывает домашнюю страницу ChatSpace `/` (Accounts Overview, чаты не открывает) и никогда не
  восстанавливает вкладки прошлой сессии (`firefox/user.js`). Открытие чата помечает его прочитанным в OnlyFans,
  поэтому ни скрипты, ни люди не заходят этой вкладкой в чаты фанов.
- Вкладка ничего не отправляет: расширение отправляет только по клику человека, а здесь никто не кликает.
- Лимиты: 2 ГБ памяти без свопа, 1.5 CPU, 1024 процесса. Сеть: `csb-egress` (выход в интернет) и `pb-control`
  (адрес `10.230.0.253`, туда ходит только API хаба к экрану). Ни один порт не опубликован.

## Сторож

`watchdog/main.mjs` раз в 30 с перезапускает Firefox (через s6), если:
- в профиле не та версия расширения, с которой Firefox стартовал (первая установка или обновление: вкладка
  загрузит новые скрипты только при новом старте);
- упал процесс вкладки (новый дамп в `minidumps/`);
- память выше 90 % лимита два раза подряд.

Перезапуски не чаще раза в 10 минут и не больше шести в сутки, после обновления расширения — через 2 минуты (Firefox
успевает записать кэши). Через 90 с после каждого старта Firefox сторож один раз нажимает F5, если на экране обзор
аккаунтов: первая страница грузится раньше, чем расширение регистрирует тап сокета, и без перезагрузки сокет ничего не
отдаёт. Больше сторож страницу не трогает: не кликает, не входит. Вход в OnlyMonster после потери сессии делает только
владелец через экран.

## Экран

Только владелец: `https://hub.gosling-agency.ru/api/v1/chatspace-browser/screen` под его входом в дашборд.
API хаба пробрасывает KasmVNC контейнера (`pb-control`, `:6901`) и подставляет пароль экрана из
`CHATSPACE_BROWSER_SCREEN_PASSWORD`. Экран закрывается, когда кончается или отзывается сессия владельца. Запасной
путь, когда API хаба лежит: `scripts/deploy-chatspace-browser.sh tunnel root@152.53.191.242`.

## Вход (один раз и после разлогина)

Нужен участник команды OnlyMonster с доступом к lora-of и lora-vip-of (просмотр чатов, без отправки) и пользователь хаба
`chatspace-server` (id 32, чаттер на этих двух страницах; пароль `CHATSPACE_SERVER_HUB_PASSWORD` в
`~/.config/agency/secrets.env`).

1. Открыть экран (ссылка выше) в браузере, где есть вход в дашборд хаба.
2. Окно cookie OnlyMonster: «Deny». Войти логином участника, код с почты — если OnlyMonster его попросит.
3. На Accounts Overview нажать «Открыть все»: оба аккаунта встают вкладками в левой колонке. В чаты фанов не
   заходить (открытый чат помечается прочитанным в OnlyFans). Домик слева от адресной строки возвращает на Overview.
4. ChatGoose. Попап у значка гуся на экране KasmVNC не рисуется (кнопка нажимается, панели нет, клавиши уходят в
   невидимую панель). Вход — на вкладке «Настройки ChatGoose» (`options.html#account`): с 3.14.5 расширение само
   открывает её, пока вкладка не вошла в хаб, а после входа возвращает ChatSpace вперёд. Логин `chatspace-server`,
   пароль — из `secrets.env` (вставить через буфер обмена экрана).

Агент делает шаг 4 без экрана: `xdotool` от `cs-firefox` на `:99` открывает
`moz-extension://<uuid>/options.html#account` и вводит пароль через `xdotool type --file -` (на stdin, не в
командной строке); uuid расширения — в `extensions.webextensions.uuids` профиля.

## Жива ли вкладка

- `scripts/deploy-chatspace-browser.sh status root@152.53.191.242`: контейнер, Firefox, версия расширения,
  перезапуски сторожа, память.
- Что на экране: `docker exec chatspace-browser sh -c 'DISPLAY=:99 /command/s6-setuidgid cs-firefox xdotool
  getactivewindow getwindowname'` (снимок KasmVNC `/api/get_screenshot` отстаёт на несколько секунд).
- Хаб сам будит владельца (вид тревог «Серверная вкладка ChatSpace», `services/chatspace-tab-watch.ts`): вкладка
  молчит 5 минут, не на ChatSpace 3 минуты (разлогинило или вкладка упала), страница не покрыта сокетом 5 минут,
  вкладка стоит в чате фана. Отчёт вкладки — раз в минуту в `chatspace_tab_reports`.
- Лента с сервера: записи `observations` вида `client.onlyfans_feed.v1` с `actor_principal_id = 32`.

## Выкладка

```sh
scripts/deploy-chatspace-browser.sh host  root@152.53.191.242   # сеть, том, пароль экрана, копия пароля для API
scripts/deploy-chatspace-browser.sh build root@152.53.191.242   # образ из слитого main с зелёным CI
scripts/deploy-chatspace-browser.sh up    root@152.53.191.242   # контейнер, ждёт healthy
scripts/deploy-chatspace-browser.sh status root@152.53.191.242
```

Деплой хаба этот контейнер не трогает. Новый Firefox ESR приходит только с новым образом (`build`, затем `up`).

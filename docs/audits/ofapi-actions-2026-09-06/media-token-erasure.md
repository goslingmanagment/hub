# CDN token custody across erasure

Fan erasure previously removed a command/action and cascaded its
`ofapi_media_token_custody` row. The completed upload remained under the page.
Its CDN token could then be handed off and reserved for a different operation.
Legacy `send_media_message_v1` also bypassed token reservation altogether.

Migration 0168 adds `ofapi_media_token_fences`: only
`SHA256(accountId + '\n' + token)` and the original opaque operation UUID. It
contains no account, page, fan, command payload, token or timestamp, and has no
parent foreign key. Existing custody is backfilled. A custody trigger preserves
reservations written by an older runtime during deployment and rejects a
different operation using the same capability.

Chat v2, owner actions and legacy media sends claim the same fence in their
reservation transaction. Multi-token failures roll back every new claim.
Legacy sends validate their retained payload before claiming and receive no
provider replay permission. Existing v2 recovery still requires its original
owner, account, endpoint, exact body, provider operation and 24-hour window.
Handoff and owner-action media validation consult the permanent fence.
Action media operation UUIDs are generated by the server, independently of the
caller-selected action ID. Choosing an erased chat operation's UUID as a new
action ID cannot impersonate its token authority.

The raw custody links, commands and responses still follow normal fan/page
erasure. A spent capability stays unavailable after those personal links are
removed; a fresh upload token and reusable vault IDs remain usable. Existing
custody can be backfilled; a reservation erased before this migration cannot
be reconstructed from the missing record.

Regression checks use real fan erasure for all three consumers, then reject
fresh action/chat IDs and legacy custody writes using the erased token. They
also check anonymous retained columns, completed upload survival, fresh-token
use, SQL backfill/hash parity, transaction rollback, v1 execution admission and
existing v2 recovery. Provider responses are synthetic; development spend is
zero OFAPI credits. Deploy the forward migration with the normal process; no
collector or production action is enabled by this fix.

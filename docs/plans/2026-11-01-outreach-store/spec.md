# «Рассылки» на хабе

Проект, 01.11.2026. Слово владельца 01.11: «продумать все так, чтобы хранились рассылки у нас на сервере» и
«дополировать эдж кейсы: это сложная работа мультиюзерская, куча разных состояний»; концепцию (схема пути фана,
два решения) он принял словами «давай делай все корректно». Его решения:

- рассылки страницы видит и может продолжить вся команда страницы (не только автор);
- пауза для фана 3 дня: кому за 72 часа писали рассылкой, «Очередью» или из «Онлайн», в новую рассылку по
  умолчанию не берём (галочка снимается); и наоборот, отправка рассылки считается касанием для «Очередей» и
  «Онлайн» (их пауза 21 день без ответа).

Код на старте: хаб main `bf65544fd`, расширение main `89f57bab` (3.15.0: рассылки в `storage.local` браузера,
`packages/core/src/domain/outreach/saved.ts`). Контракт: `packages/contracts/src/outreach.ts`,
`routes-outreach.ts`; возможность `outreach-store-v1`.

## 1. Что и зачем

Окно «Рассылка» расширения: общий текст, фаны из Spenders («Кому»), версия для каждого (Fix,
`draftPurpose: "outreach"`), правка человека, отправка одним кликом на фана (Fansly: фон расширения шлёт
`POST /message`; ChatSpace: отправка карточки через очередь ChatSpace, бронь хаба `preview-reply`).

До сих пор вся рассылка жила в одном браузере. Отсюда дыры:

- другой компьютер или коллега рассылку не видят, передать смену нельзя;
- на Fansly две вкладки одного человека могут отправить одному фану обе (окно ~0,7 с между проверкой и записью);
- два человека с двумя рассылками пишут одному фану в один час, никто этого не видит;
- итоги (ответил, купил) считает вкладка, пока открыта, и только первый час.

## 2. Что хранит хаб

`client_outreaches`: рассылка.

| Поле | Что |
|---|---|
| `id uuid` | выдаёт клиент (рассылка, начатая без хаба, сохраняет id) |
| `page_id` | страница; другой странице рассылка не видна (404/409 `outreach_not_found`) |
| `author_user_id`, `created_at` | автор: тот, чьё первое сохранение; `created_at` из тела только при первом, не старше 30 дней |
| `updated_by_user_id`, `updated_at` | последнее изменение (сохранение или отправка) |
| `text` ≤ 5000 | общий текст |
| `with_media bool` | у предложения есть медиа (для списка) |
| `settings jsonb` ≤ 32 КиБ | состояние окна (кому, условия, предложение); хаб не читает |
| `fan_order text[]` ≤ 1000 | порядок фанов, когда версии написаны |

`client_outreach_fans`: фан рассылки, ключ `(outreach_id, fan_ref)`; `page_id`; `fan_id` → `fans` (cascade).

| Поле | Что |
|---|---|
| `version`, `basis`, `generation_ref`, `version_at` | версия Fix; `basis` — имя общего текста, по которому она написана (хэш клиента; хаб не сравнивает) |
| `edit`, `edited_by_user_id`, `edited_at` | слова человека; null — стоит версия Fix |
| `send_state` | null / `sending` / `sent` / `uncertain` / `failed` |
| `attempt_id uuid`, `sender_user_id`, `clicked_at`, `ticket_until` | бронь |
| `sent_at`, `platform_message_id`, `failure_code`, `resolved_by` | итог отправки |
| `sent_text` ≤ 5000, `sent_media jsonb` | что ушло (как прислал клиент) |

Индексы: одна живая бронь на фана страницы, `(page_id, fan_ref) where send_state = 'sending'` (живость билета
проверяет код: просроченная бронь читается `uncertain` и не мешает); отправки фана по времени для касаний
`(page_id, fan_ref, clicked_at desc) where send_state is not null`; список страницы `(page_id, updated_at desc)`.

Хранение: 90 дней без изменений; старые удаляются при чтении списка страницы (лениво) или общей уборкой, если она
есть. Стирание фана уносит его строки (cascade), страницы — всё.

## 3. Кто что видит и делает

- Любой, кому выдана страница (`requireClientGrantedPage`), видит все её рассылки, открывает любую, пишет в ней и
  отправляет из неё. Автор и каждое действие подписаны логином (как в «в разговоре»), `isMe` для своих.
- Возможность `outreach-store-v1`, токен устройства, узкий токен. Флага страницы нет (как у «Очередей»): старый
  клиент рассылки на хаб не пишет; без возможности расширение хранит рассылки в браузере, как в 3.15.0.

## 4. Сохранение (`clientOutreachSave`)

- Первое сохранение id создаёт рассылку, автор — вызывающий. Id чужой страницы: 409 `outreach_not_found`.
- Каждое поле — последнее слово: кто сохранил позже, тот и прав (`text`, `withMedia`, `settings`, `order`).
  Конфликтов по номерам ревизий нет: двое правят одну рассылку редко, а потеря неотправленной правки поправима.
- Изменения фанов (до 50 за раз): версия с `basis` (и `generationRef`), `null` — отпустить; слова человека,
  `null` — назад к версии Fix. Фан с бронью (`sending`/`sent`/`uncertain`) их не принимает: он в `kept`, всё
  остальное сохранение проходит. Фан, которого хаб не знает на странице: 409 `fan_not_found` (весь запрос).
- `order` целиком; `[]` — версии не написаны. Фаны с отправкой остаются в `fans` ответа, даже если их нет в
  `order`: отправка не теряется никогда.
- Ответ: вся рассылка после сохранения (как `clientOutreach`) + `kept`.

## 5. Отправка (`clientOutreachSend`)

Правила брони (один переход под `pg_advisory_xact_lock('outreach-fan:<page>:<fan>')`, как у брони приветствий):

| Действие | Когда проходит | Что делает | Иначе |
|---|---|---|---|
| `claim` | у фана этой рассылки нет отправки или она `failed`; и у фана страницы нет живой брони другой рассылки | `sending`, билет 120 с, кто, когда, текст и медиа; строка фана создаётся, если её не было | `taken` (эта рассылка: ушло, могло, в пути; кто и когда в `fan.send`), `busy` (другая рассылка шлёт ему прямо сейчас) |
| `sent` | та же попытка; `sending` или `uncertain` | `sent`, `sent_at`, id сообщения | `not_yours`; повтор — `ok` |
| `failed` | та же попытка; `sending` или `uncertain` | `failed` с кодом: фана можно бронировать снова | `not_yours`; повтор — `ok` |
| `uncertain` | та же попытка; `sending` | `uncertain`: никогда не бронируется снова | `not_yours`; повтор — `ok` |
| `record` | у фана нет отправки; `clickedAt` не старше 30 дней и не в будущем | отправка, сделанная до хаба (рассылки 3.15.0 из браузера): `sent` или `uncertain` как есть | `taken` |

- `sending` с истёкшим билетом читается как `uncertain` везде (ответы, список, касания) и в базе может так и
  остаться: запись при чтении не обязательна.
- Поздний `sent` той же попытки превращает `uncertain` в `sent`. Поздний `failed` той же попытки тоже принят:
  неизвестная отправка держит фана, никто другой его не забронировал, клиент знает отказ точно.
- Каждое действие, кроме `claim`, журналируется в `observations` первым (`client.outreach_send.v1`), как отчёт
  «Очереди».
- Ничего не повторяется само. Неизвестную отправку никто не шлёт снова, ни из этой рассылки, ни повтором брони.

Подтверждение по архиву: `uncertain` (и просроченный `sending`) моложе 30 дней при чтении рассылки ищется в
архиве хаба: сообщение страницы этому фану в его чате, время в [клик − 60 с, клик + 30 мин], текст совпадает с
`sent_text` (сравнение после нормализации: HTML-теги прочь, сущности раскрыты, пробелы схлопнуты, регистр
нижний; совпадение первых 60 символов). Нашлось — `sent`, `sent_at` и id сообщения из архива,
`resolved_by = 'archive'`. Обратного вывода («не ушло») нет.

## 6. Итоги

Для `sent`: ответил — первое сообщение фана в архиве в течение 72 ч после отправки (время, текст ≤ 500);
купил — деньги фана (`transactions`, gross > 0, без возвратов и чарджбэков) в течение 7 дней после отправки:
сумма и первое время. Тот же счёт, что у результатов «Очередей» (`listFanQueueResults`); читатель для одного
фана рядом с ним. Список рассылок считает те же числа по всем фанам одним запросом.

## 7. Касания (`clientOutreachTouches`) и паузы других окон

- Ответ: фаны страницы, которым за 72 ч писали: рассылка (`sent`/`uncertain`/`sending`, время отправки или
  клика), «Очередь» (`fan_queue_items` sent, `done_at`), «Онлайн» (`online_attempts` sent). Последнее касание
  на фана: когда, откуда, кто, какая рассылка. Не больше 10 000.
- Расширение берёт его для условия «Кому» «Без тех, кому писали за 3 дня» (по умолчанию включено) и для
  предупреждения карточки «ему ушла другая рассылка».
- «Очереди» и «Онлайн»: отправка рассылки без ответа фана теперь держит его так же, как их собственная
  отправка: 21 день (`fan-queue-rules.ts`, правила «Онлайн»). Личное сообщение (атрибуции) уже учитывается
  как было.

## 8. Расширение (для понимания; делается в chat-extension)

- Хаб — главная копия, `storage.local` — копия и очередь неотправленных изменений: рассылка открывается сразу из
  копии, изменения уходят на хаб не чаще раза в 2 с, без хаба копятся и досылаются.
- Окно с открытой рассылкой перечитывает её раз в 15 с и при возврате на вкладку: чужие отправки и правки видны.
- Перед каждой отправкой `claim`; без хаба отправка с предупреждением «хаб не отвечает», бронь досылается
  `record`-ом после.
- Рассылки 3.15.0 из браузера уходят на хаб один раз (`createdAt`, `record` для отправок).
- Предупреждения карточки на обоих сайтах (можно пройти): коллега пишет ему сейчас (15 мин), он написал после
  версии, ему ушла другая рассылка (касания), купил предлагаемое.

## 9. Крайние случаи

| Случай | Что будет |
|---|---|
| Два клика по одному фану (вкладки, компьютеры, люди) | хаб пропускает первый, второй видит «Уже отправил Гриша в 14:20» |
| Две рассылки шлют одному фану в одну секунду | вторая получает `busy`, через билет видит отправку первой как касание |
| Вкладка закрылась после брони | через 120 с «Могло уйти»; архив за минуты ставит «Ушло», если сообщение есть |
| Отказ платформы | `failed` с кодом, «Отправить ещё раз» (новая бронь) |
| Коллега правит версию, пока я жму «Отправить» | уходит то, что видел я (текст в брони), правка коллеги остаётся в `kept` |
| Коллега нажал «Очистить» | отпущены неотправленные версии; отправленные и бронь не трогаются |
| Рассылка другой страницы по id | 404/409 `outreach_not_found` |
| Сняли доступ к странице | 409 `not_granted`; его отправки остаются с его логином |
| Фан стёрт | его строки уходят каскадом; в `order` его id остаётся строкой, клиент его не покажет |
| Хаб не отвечает | расширение работает по копии, отправка с предупреждением, бронь потом `record` |

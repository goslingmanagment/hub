# Project Browser

**Контекст**

У агентства шесть страниц на Fansly. Чаттеры работают в своих браузерах с нашим расширением и отдельными менеджерскими доступами.

Hub круглосуточно собирает сообщения, подписчиков, доходы и другие данные для дашбордов, ИИ-функций и отчётов — даже когда чаттеры не в сети.

**Как работает сейчас**

В Hub сохранён токен из личной браузерной сессии владельца. Сервер самостоятельно обращается к API Fansly через прокси соответствующей страницы. Полноценный браузер в этом процессе не участвует.

Передаётся основной токен `authorization`, но дополнительные параметры — `fansly-client-id`, `fansly-session-id`, `fansly-client-check` — у нас не заполнены и не отправляются. Часть остальных заголовков воспроизводит ранее записанные браузерные запросы.

Основное опасение — возможное усиление проверок Fansly, при котором отличия нашего клиента станут проблемой.

**Что хотим**

Для каждой страницы на нашей инфраструктуре должен работать отдельный постоянный браузер со своим профилем и собственной авторизованной сессией Fansly.

Все обращения Hub к Fansly должны выполняться через этот браузер. Hub автоматически задаёт необходимые действия, получает результаты и сохраняет данные. Работа не зависит от браузеров чаттеров.

Цель — сделать работу максимально естественной и неподозрительной с точки зрения Fansly: использовать настоящий браузер, постоянную сессию и закреплённый за страницей прокси.

Конкретный способ управления браузером и выполнения операций внутри него выберем позже.

**Производительность под нагрузкой**

- Требования к пропускной способности запросов и минимальной задержке событий должны выполняться при одновременной работе всех шести страниц.
- Загрузка истории, массовые операции и передача медиа не должны задерживать получение и обработку свежих событий WebSocket.
- При выборе архитектуры эти требования проверяются под нагрузкой. В спецификации нужно задать измеримые критерии: число запросов и параллельных операций, интенсивность событий и допустимую задержку до доступности информации в Hub.

**Возможности и условия**

- Поддерживаются любые необходимые действия: сбор данных, отправка сообщений, публикация постов, создание и управление отложенными публикациями, загрузка медиа в Vault.
- Серверный браузер **не должен отправлять отметки о прочтении сообщений**.
- Остальные фоновые действия сайта, включая статус присутствия, должны быть понятными и управляемыми.
- На страницах включена **2FA**. Владелец вручную входит через удалённый экран и вводит код. При необходимости повторной авторизации система сообщает об этом.
- Прокси остаются прежними: резидентские SOCKS, по одному на страницу.
- Работа чаттеров и расширения не меняется.
- После перезапуска сохраняется браузерный профиль, а Hub продолжает работу с сохранённого места.

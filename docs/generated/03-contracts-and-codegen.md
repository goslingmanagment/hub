# API Contracts, Codegen & the Vendored SDK

The `packages/contracts` package is the single declarative source for the
kernel's HTTP surface: every route's request/response Zod schemas and its
authorization policy live in `packages/contracts/src/routes.ts`, and a single
generator (`pnpm contracts:generate`) boots the real API server in-memory,
harvests its route table, and emits three downstream artifacts — the OpenAPI
snapshot, the `docs/generated/authorization-policy.md` document, and the
generated `@kernel/sdk` package. A separate script re-vendors a compiled copy of
that SDK into the two client repos. This document maps that machinery and the
cross-repo drift gates that key off it. It is the boundary the desktop app and
extension see.

## 1. Package layout

`packages/contracts/src/` (barrel `index.ts:1-4` re-exports `routes`,
`authorization-policy`, `domain-event-cursor`, `sdk-runtime`):

| File | Role |
|---|---|
| `routes.ts` (6,023 lines) | Every Zod request/response schema plus the `routeSchemas` registry and the `RouteAuthPolicy` declarations |
| `authorization-policy.ts` | `renderAuthorizationPolicyMarkdown()` — turns the booted server's route→auth table into `docs/generated/authorization-policy.md` |
| `sdk-runtime.ts` | The `@kernel/sdk` runtime: the typed `KernelClient`, `createKernelClient`, error taxonomy, and the SSE/stream/gateway helpers, all typed off `routeSchemas` |
| `domain-event-cursor.ts` | The opaque base64url per-account cursor codec shared by the v2 SSE endpoint and the SDK (see `11-events-and-streaming.md`) |
| `generate.ts` | The `contracts:generate` entrypoint (boots the server, writes all artifacts) |
| `generate-sdk.ts` | `buildSdkFiles()` — the pure function that emits the generated `packages/sdk` files |

The generated SDK itself lives in `packages/sdk/src/` (`index.ts`, `meta.ts`,
`operations.ts`), all carrying a "Generated by `pnpm contracts:generate`. Do not
edit by hand." banner.

## 2. The route registry and its Zod schemas

`routeSchemas` (`packages/contracts/src/routes.ts:3907`) is an object of ~150
named operations (150 top-level keys; 149 carry an inline `auth` block). Each
entry is a Fastify-shaped schema: optional `params`, `querystring`, `body`, a
`response` map keyed by status code, and — added by kernel Stage 19 — an `auth`
block. Shared value vocabulary is imported from `@agency_hub_core/shared`
(`routes.ts:1-16`): `PERIOD_OPTIONS`, `SPENDER_PERIOD_OPTIONS`, `platforms`,
`transactionTypes`, `transactionStates`, `userRoles`, `aiUsageFeatures`,
`fanFlagTypes`, etc., so the wire enums cannot drift from the domain enums.
Money on the wire is `z.number().int()` mills (`routes.ts:19`); business dates
are validated via `isValidBusinessDateString` (`routes.ts:21-23`).

### The declarative auth policy

`routeAuthPolicySchema` (`routes.ts:3664-3671`, `.strict()`):

```
{ kind: "public"|"hmac"|"monitoring"|"session"|"any-session"|"owner-session"|"apiKey"|"any",
  roles?: userRole[] (nonempty),   // reserved; unused today
  scope?: "page"|"none" }
```

- `scope: "page"` tells the middleware to resolve the `:pageLabel` path param and
  require page access before the handler runs; page ids derived from query/body
  stay handler-checked (`routes.ts:3660-3663`).
- `routeSecurityFromAuth(auth)` (`routes.ts:3676-3696`) DERIVES the OpenAPI
  `security` array from the `kind`: `monitoring` → `cookieAuth` OR
  `monitoringTokenAuth`; `session`/`any-session`/`owner-session` → `cookieAuth`;
  `apiKey` → `bearerAuth`; `any` → `cookieAuth` OR `bearerAuth`; `public`/`hmac`
  → `undefined` (HMAC signature over the raw body cannot be expressed as an
  OpenAPI security scheme, so the webhook documents it in prose). The swagger
  transform in the server injects this so the published contract cannot disagree
  with what the middleware enforces.

The scheme names match the server's `securitySchemes` (`cookieAuth`,
`bearerAuth`, `monitoringTokenAuth`). The human-readable descriptions of each
`kind` live in `authorization-policy.ts` (`KIND_DESCRIPTIONS`, `:15-24`).

## 3. The generate pipeline (`pnpm contracts:generate`)

`package.json:21`: `contracts:generate` = `node --import tsx/esm
packages/contracts/src/generate.ts`.

`generate.ts:10-80` (`main`):
1. Builds the API server with a fully synthetic in-memory `AppContext`
   (`databaseUrl: ""`, zero-filled 32-byte encryption key, `pool`/`db`/`adapter`
   as `{} as never` — no database, no platform clients) so the surface can be
   generated with no infrastructure (`generate.ts:11-51`). `buildApiServer`
   skips the pg-boss block when `databaseUrl` is empty.
2. `server.ready()` then `normalizeOpenApiDocument(server.swagger())` and writes
   `reference/agency-hub.openapi.json` (`generate.ts:54-57`). `normalizeOpenApiDocument`
   (in the server module) sorts paths deterministically (swagger emits them in
   route-registration order, which the module extraction shuffles) and rewrites
   the credits `.csv` response content-type to `text/csv`.
3. Writes `docs/generated/authorization-policy.md` from
   `renderAuthorizationPolicyMarkdown(server.routePolicyTable)` — the same booted
   route table carries the declared auth policies (`generate.ts:59-63`).
   **This is the one file in `docs/generated/` owned by `contracts:generate`, not
   by the prompt-1-map regeneration.**
4. Emits the generated `@kernel/sdk` files via `buildSdkFiles(...)` and writes
   each into `packages/sdk/` (`generate.ts:67-76`).

The `reference/agency-hub.openapi.json` snapshot is ~1.78 MB (`reference/`
directory also holds hand-kept third-party specs: `fansly_api_spec.md`,
`onlymonster_*` — the latter now historical).

## 4. The generated SDK (`buildSdkFiles`, `generate-sdk.ts`)

`buildSdkFiles(input)` (`generate-sdk.ts:27-180`) is a pure, deterministic
function (two runs must be byte-identical — a tested property). It:

- Cross-checks the booted route table against `routeSchemas`: every registry key
  must appear in the route table and vice versa, else it throws
  `manifest/registry mismatch` (`generate-sdk.ts:36-42`). A route key registered
  twice also throws (`:31-34`).
- Computes `KERNEL_CONTRACT_HASH = sha256(the exact normalized OpenAPI document
  bytes)` (`generate-sdk.ts:44-47`) — any schema-shape change (renamed field, new
  required param) changes it; this is the value the cross-repo drift gates key
  off.
- Emits `src/operations.ts` (the `kernelOperations` manifest: `{method, path}`
  per registry key, sorted, recovered from the route table), `src/meta.ts` (the
  contract hash + SDK version), `src/index.ts` (thin re-exports + `createClient`),
  `package.json`, and `README.md`.

Current values in the tree: `KERNEL_CONTRACT_HASH =
"e8c867e8861a47a3b781a6c1ba634f99542d439a46d61effb8637e495787baae"`,
`KERNEL_SDK_VERSION = "0.1.0"` (`packages/sdk/src/meta.ts:4-5`).

### The runtime (`sdk-runtime.ts`)

All the SDK's moving parts live in the contracts package, typed directly off the
Zod registry so request/response types cannot drift from the server
(`sdk-runtime.ts:5-10`). `KernelOperationKey = keyof routeSchemas`
(`sdk-runtime.ts:17-18`). Request/response types are derived from each schema's
`z.input`/`z.output` (`sdk-runtime.ts:37-56`). The generated `packages/sdk`
package contains ONLY machine-written artifacts — `createClient` wraps
`createKernelClient(kernelOperations, options)` (`packages/sdk/src/index.ts:40-42`).

`SDK_EXCLUDED_OPERATIONS` (`sdk-runtime.ts:26-34`) — six operations with no
plain request/JSON-response shape, reachable only via `client.raw(...)`:
`ofapiWebhookReceive` (HMAC server intake), `eventsStream` + `eventsV2Stream` +
`aiGatewayStream` (SSE, served by dedicated stream helpers), `ofapiReadGateway`
(wildcard proxy passthrough), `adminOfapiCreditsLedgerCsv` (text/csv). The
runtime also exports the stream helpers `streamAiGateway`, `streamAiFeature`,
`subscribeSyncEvents`, `subscribeDomainEvents`, `ofapiRead`, and
`decodeDomainEventCursor` (`packages/sdk/src/index.ts:22-36`) so out-of-workspace
consumers get typed access to the SSE and gateway boundaries.

## 5. Vendoring into client repos (`scripts/vendor-sdk.mjs`)

Client repos (`chatgoose_desktop_fable`, `chatgoose`) cannot resolve
`workspace:*` deps and must not compile core's `.ts` under their own strictness
flags, so the SDK is shipped as a **self-contained compiled bundle**
(`vendor-sdk.mjs:2-10`). Usage: `node scripts/vendor-sdk.mjs <target-dir>`
(e.g. `../chatgoose_desktop_fable/packages/kernel-sdk`).

The script (`vendor-sdk.mjs`):
- Reads the current `KERNEL_CONTRACT_HASH` out of `packages/sdk/src/meta.ts`
  (aborts if absent — "run `pnpm contracts:generate` first", `:47-53`), and the
  source commit via `git rev-parse HEAD`.
- Stages a source subset into a temp dir: the three dependency-free shared
  modules the contract registry reaches (`types.ts`, `time.ts`,
  `spender-retention.ts`, `:63-69`), the contracts files (`routes`,
  `sdk-runtime`, `domain-event-cursor`, `authorization-policy`, `index`,
  `:72-74`), and the sdk files (`index`, `meta`, `operations`, `:77-79`),
  rewriting workspace specifiers to relative paths and dropping `.ts` extensions
  (`stageFile`, `:38-45`).
- Compiles it with core's own `tsc`/`zod`/`@types/node` (`:82-115`), then ships
  `dist/` (js + d.ts) plus a generated `package.json` (name `@kernel/sdk`, only
  external dep `zod`), a `kernel-sdk.vendor.json` recording `{contractHash,
  sourceCommit, source}`, and a README (`:117-162`).

The vendor manifest's `contractHash` is what each client's drift CI compares
against core@main; the eventual distribution mechanism (DP 10) is git-tag installs
(`@kernel/sdk: github:<org>/core#sdk-vX.Y.Z`), keeping the `@kernel/sdk` import
surface identical (`vendor-sdk.mjs:158-161`, `generate-sdk.ts:152-169`).

## 6. Drift gates keyed off these artifacts

- `KERNEL_CONTRACT_HASH` (sha256 over the normalized OpenAPI document) is the
  cross-repo drift key; a consumer's pinned hash mismatching core@main's is a
  contract-drift build failure (`generate-sdk.ts:44-47`, `meta.ts:3`).
- `tests/contracts-auth-declarations.test.ts` pins that every `routeSchemas`
  entry declares a valid `auth` policy (the auth-policy middleware in the server
  fails closed on any route lacking a declaration). Companions
  `tests/contracts-route-security.test.ts`, `tests/contracts-spender-validation.test.ts`.
- `tests/dashboard-sdk-ban.test.ts` forbids direct `fetch(`/hand-rolled clients
  in `apps/dashboard/src/api` — the dashboard consumes the same `@kernel/sdk`
  surface (see `20-dashboard-frontend.md`).

## 7. What crosses this boundary

The contract surface is what the three consumers see:

- **Dashboard** (in-workspace) imports `@kernel/sdk` resolving to
  `packages/sdk/src/index.ts` directly (cookie auth).
- **Desktop app / extension** (out of workspace) consume the vendored compiled
  bundle (bearer API-key / device-token auth), pinned by `KERNEL_CONTRACT_HASH`.
- Requests/responses are Zod-validated on both ends; the published
  `reference/agency-hub.openapi.json` and `docs/generated/authorization-policy.md`
  are the human-readable projections of the same registry.

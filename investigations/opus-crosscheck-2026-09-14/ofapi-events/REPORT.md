**С чем совпали.** D1 и E1 совпадают с прежними `events-ofapi/O1,O2`: stale audience REST snapshot может перезаписать более свежий expiry webhook; list collectors парсят до capture. `fan_identities` вообще не журналирует successful bodies, а transaction backfill пишет normalized monetary rows без original response journal. Эти пути следует перевести на существующий capture seam до mapper. Современный governed mirror уже сохраняет bytes до parse; его не нужно заново «чинить». У unread reconcile D3 дополнительная проблема: отсутствующий `unreadMessagesCount` превращается в 0 и записывается как authoritative значение.

**Самое существенное новое относительно прежнего OFAPI baseline — D2.** `runOfapiPendingReconcile` исключает только `page.status=blocked`. Реальная функция с fake I/O retire'ит stale pending при `written + budget_exhausted` и `written + page_cap`, в обоих случаях `retireCalls=1`; при `blocked` — 0. Это доказанный control-path defect, а не доказанное списание на production. Исправление требует положительного per-page evidence завершённого окна; проверка `paginationStopReason` необходима, но также нельзя принять полноту при malformed/отброшенных in-window строках. **Другие дополнительные проблемы.** B4: captured 404 остаётся в checkpoint, Resume локально снова потребляет тот же ответ, paused job не разрешает следующее scheduled window. **C4/F1–F4 требуют более точных формулировок.** Автоматическая полноценная catch-up гарантия после outage не найдена; есть современный mirror, интерактивные reads и pending-only rescan. Поэтому «всё держится на вебхуках» слишком широко. У sync health есть deploy consumer — утверждение «нет потребителя» буквально неверно; постоянный consumer именно sync health в repo не найден. Ops watchdog scheduler/sampler уже существует. Standing delivered incidents не напоминаются, но failed open delivery уже повторяется bounded; новое открытие resolved incident и повтор existing incident различны.

Health действительно может пропустить stale-success через running/pending branches; финансовый override считает `transactionCount>0` достаточным для вечного `up_to_date`; общий webhook-silence signal маскируется событиями другого аккаунта и presence. При этом `latestTransactionAt` нельзя просто превратить в финансовый heartbeat: тихий бизнес может не иметь новых платежей. Sidebar summary отдельно проверяет auth, поэтому общий тезис «весь sidebar всегда green» не принимается без собственного trace. `/health/sync` без `/api/v1` при собранном dashboard попадает в SPA fallback и может вернуть HTML200. Предложенные семь SLO и пороги F4 пока design choices: нужны scope, cadence, отсутствие traffic и no-sample semantics.

**Два предложения в текущем виде отклонены.**

- **O7-01:** zero-stamp pass не доказывает stable unmapped cohort. Body unavailable→available, исправленный parser, reattached partition, erasure unlock и late commit ниже cursor могут случиться без изменения binding fingerprint. Общий `afterId` с full retry раз в 6–24 ч задерживает уже исправившийся долг. Нужны durable reasoned retry sets и соответствующие wakeups; отдельно parked unmapped cohort допустим с гарантированным bounded revisit. Reference counterexample в probe явно обозначен моделью, не DB execution.
- **O7-07:** пропуск advancing recovery ради 60s cooldown нарушает [действующий event-time law](/Users/dmitriy/code/goose/hub/docs/error-handling.md:217). Success10 → success50 → поздний failure30 должен подавляться watermark50. Пропущенный success50 оставляет watermark10 и открывает уже восстановленный incident. Безопасны no-op для identical/older covered evidence и удаление лишнего producer в O7-06; tombstone, resolve и outbox должны остаться атомарны. Throttle напоминаний не равен throttle recovery state.

**Оптимизации событий совпадают частично.** O7-05 = `OBS-09-02`: один process-owned worker hub вместо двух подтверждён источниками; independent smoke guards/checkpoint/replay сохраняются. С активным API общее число live hubs меняется 3→2, не «вдвое во всём Hub». O7-06 = `04-A`: exact canonicalization зря делает fleet binding census и global recovery; narrow lookup разумен, но narrow success не доказывает global recovery, которое остаётся у полного sweep. Existing probe считает пять подготовительных SQL без BEGIN/COMMIT, семь с ними; «7–9» требует явного знаменателя.

O7-04 пересекается с `P05-1`, `P05-2`, typed filtering и `GF12-01`. Проверенный runtime registry содержит **14 domain-event readers / 48 типов / 0 overlaps**, читающих собственные delta ranges. AI acceptance читает observations, smoke/workboard — другой контур O7-05. «16 одинаковых чтений» и «−15/16 декодирований» не доказаны. Metadata readiness полезен; общий payload cache требует независимых watermark/scanned-through, erasure/rebuild и account fault-isolation. [Сохранённый actual-function census](/Users/dmitriy/code/goose/hub/investigations/sync-optimization-swarm-2026-09-13/05-projections/probe-results.json).

**§5 S5-ofapi402 — conditional.** Balance freshness и retained-response reuse подтверждены в узких исходниках; blanket «402 без списания» не принимается. Accounting helper даёт exact0 при reported0, exact2 при reported2 и no row при полном отсутствии metadata. Governed capture сначала сохраняет reserved estimate независимо от HTTP status, затем уточняет расход, только если он известен. Это не доказательство vendor billing. Legacy stale-low balance может выпустить probe; governed stale balance обычно блокируется, исключение ограничено eligible live scope. Поэтому общий тезис не означает одну и ту же freshness policy для всех REST-путей.

Проверенный actual helper для exact bytes дал different=false/equal=true/missing=false. JSON whitespace/key order намеренно не входят в canonical identity; это не сохранение произвольной wire-формы в JSON representation. Existing forced-digest integration test прочитан, но не запускался; нулевой current collision count и доступность всех retained pointers не доказаны.

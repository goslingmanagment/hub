11–12 сентября — **30 699,5**, то есть **+0,426%**. Окна не сопоставлены по
нагрузке; старые счётчики потерь неполны. Это описательная сводка, она не
доказывает причинную экономию. Экономия ≥50% не подтверждена; event → reader p95/p99 не измерены.

Готовые ограниченные SQL и квитанция: [material query cost](material-query-cost/REPORT.md).
Более привилегированная роль не использовалась.

Свежий read-only снимок **14 сентября 02:14:59 UTC**: API, worker, scheduler
healthy, 0 рестартов, прежние source `38032636` и image `c443947a…`.

   разрешённый production rollout и проверить те же source/image/health вместе
   с профильными smoke-проверками. Этот отчёт не является квитанцией deploy.
2. Для material-check нужен доступ к трём таблицам в пределах утверждённой
   read-only роли. Без него измерение стоимости и reader coverage не выполнено;
   семь дней ожидания этот технический блокер не устраняют.
3. Выполнить подготовленный парный W0 probe и наблюдение непрерывности ≥6 часов;
   для C1/C2b — собрать оставшееся coverage/presence/policy evidence. Только
   после критериев соответствующего этапа возможны следующие включения.

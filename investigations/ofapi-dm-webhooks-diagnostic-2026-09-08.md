## 1. Как работает сейчас (код 21e0ee33, подтверждено продом)

- nginx → `POST /api/v1/ofapi/webhook` (`modules/ingest/index.ts:104`) →
  HMAC по сырым байтам (текущий/предыдущий/pending секрет) → claim
  `ofapi_webhook_events` по `X-OFAPI-Idempotency-Key` (`on conflict do nothing`)
  + `observations(source='webhook', idempotency_key=evt_…)` в одной транзакции →
  **200 только после durable-записи** (`ofapi-webhooks.ts:131-220`) → best-effort
  `boss.send`. Провал до записи = не-2xx → провайдер повторяет (3 попытки,
  ~10 с и ~100 с). Повтор ключа → 200 `duplicate`. Typing/online/offline без
  ключа → локальный UUID. Тот же ключ с другим телом → `fact_conflict`, второе
  тело не применяется (на проде 3 шт. за 7 дней, все `messages.sent` PPV с
  медиа).
- Воркер: pg-boss `ofapi.events.process.v2` (retryLimit 2, без DLQ) + минутный
  sweep `pending` старше 30 с (`ofapi-events.ts:240-395`). Обработка: нет
  активной страницы по `ofapi_account_id` → терминальный `skipped`; иначе
  settle + `pg_notify` в одной транзакции. Пост-settle: горячее хранилище
  `page_dm_threads`/`page_dm_messages` (текст, отправитель, tip, replyTo; цены
  и медиа нет) и холодный архив `dm_message_archive` (`text_plain`,
  `price_mills`, `is_opened`, `is_tip`, `media_metadata` — только id/тип/размеры,
  подписанные URL не хранятся и истекают в течение часов). Провал проекции
  ретраится 5 раз, потом терминальный `failed`, дальше только ручной
  `replayLocalOfapiWebhook`.
- SSE: NOTIFY — только wake-up, десктоп читает журнал от `Last-Event-ID`,
  при выпадении из окна — 409 → snapshot. Строки `skipped` не получают
  `fanout_seq` и в SSE не попадают никогда.
- Канонизация: семья `webhook/ofapi` v5 отдельным sweep; из DM-вебхуков —
  `message.received/sent/deleted/ppv_unlocked`, `tip.received`; деньги только
  из `transactions.new`.
- **Что осталось от REST для OF DM:** только список чатов
  `sync:onlyfans:dm_conversations` раз в 6 ч на страницу
  (`OFAPI_DM_RECONCILE_INTERVAL_MINUTES=360`; на проде 05:50/06:04, 11:50/12:04,
  18:20/18:34, 00:20/00:34Z) — обновляет головы тредов и unread, тел не тянет;
  readthrough-сверка при открытии чата в десктопе; capture-jobs по seed
  владельца (≤20 целей). Стрим `dm_messages` для OF списан
  (`executor-handlers.ts:2613-2628`), писателя `rest_backfill` в коде нет,
  OnlyMonster-опрос DM удалён. Все OF-треды в Read Plane — `pending_backfill`,
  `lastMessageSyncAt: null`.

## 4. Не проверено / ограничения

- 05.09 13:56Z → 06.09 03:48Z: истории доставок нет (сбор включён позже); один
  502 06.09 03:35Z без подтверждения повтора.
- Полная суточная сверка архив↔вебхуки не сделана: `read_only` не видит
  `dm_message_archive`/`ofapi_webhook_*`, у Read Plane нет датасета сообщений по
  дням. Сделаны выборочные проверки (3 свежих сообщения + первые после
  переезда) — все в архиве.
- Десктоп (of-desktop) как получатель SSE не проверялся; клиента в этом репо нет.
- Семантика `fact_conflict` (что именно отличалось во втором теле) не разбиралась.
- Read Plane: два чтения транскрипта подряд вернули пустой `data` без
  `blockers` и затем те же окна вернули строки; вероятно 429 по concurrency
  общего ключа (второй агент), ошибка была проглочена парсером — не баг плоскости.

## 5. Решения владельца (не сделано, только перечень)

1. Гидратация окна 03.09 20:22Z–05.09 13:56Z по OF-тредам (платно; список
   тредов — по `lastMessageAt`/`lastFanMessageAt` в окне плюс активные треды).
2. Проверка окна в `ofapi-webhook-recovery.ts:110` — секундная точность границ
   (или `from` округлять вниз до секунды) до 14.09 23:45Z, иначе окно уйдёт.
3. Канонизатор: исключить отвязанные `native_account_ref` из sweep или
   durable-курсор; сейчас каждый рестарт воркера начинает круг заново.
4. Для окон без вебхуков — периодическая REST-сверка тел DM по головам
   тредов (`lastMessageAt` > newest stored) или хотя бы короче 720 мин
   silence-инцидент; пересмотр терминального `skipped` при позднем биндинге.
5. `GRANT SELECT` роли `read_only` на `ofapi_webhook_*`, `dm_message_archive`,
   `page_dm_*` — без этого каждая такая проверка идёт через сырые `observations`.

CI was repeating expensive checks and builds, and its reuse boundary could omit executable evidence. This change makes reuse conservative, preserves required checks, and removes avoidable work from full runs.

- Full fingerprints omit only reviewed regular Markdown. A separate integration proof permits dashboard source/public edits to reuse validated backend checks; tests, helpers, configs, dependencies, shared packages and unknown paths remain inputs.
- Draft PRs skip heavy jobs with a failing required gate. Ready and title/base edits run admission; description edits neither cancel an active run nor replace its Quality Gate. Proof producers, expiry and rerun uploads are validated.
- Docker typechecks by default. CI reuses its explicit type result, builds the image once with Buildx layer cache, and retains both image smokes. Unit tests use two isolated workers; integration files remain serial.
- DB workers import pure context constants instead of Testcontainers global setup. Partial-schema fixtures lazily load the same production migrator inside the cleanup boundary. The scale test keeps all 120,000 observations, 1,000 projections and 151-burst assertions; synthetic 100ms WAN waits remain in the explicit benchmark.
- A separate reliability commit fixes a pre-existing typed-export clock mismatch found during regression testing: preliminary due selection now uses the Node clock already used by creation, approval and leasing. Real-DB tests prove creation/approval under clock skew and prevent early dispatch of future ready/retry_wait tasks. Locking, deadlines, spend limits and request fencing are preserved.
- The read-only cost reporter includes attempts, deduplicates carried jobs and labels incomplete samples. Repository squash defaults have been read back as PR_TITLE + BLANK.

# Первичный ответ Fable 5.1

> Уточнение после независимой проверки: утверждение об одинаковом риске смены языка для Alt+цифры и Alt+Shift, а также гипотеза о конфликте macOS Cmd+Shift+V с pasteAndMatchStyle исправлены в [повторном ответе](fable-revised-response.md). Основная рекомендация сохранилась.

**Вердикт (предварительный, без живых тестов)**

**Рекомендация:** не переводить desktop на Alt и не вводить Alt+1..5. Добавить в desktop комбинации расширения как *дополнительные алиасы* (не переключаемый профиль в настройках): на macOS ⌘⇧+буква, на Windows/Linux Alt+Shift+буква. Существующие Ctrl/⌘+буква остаются, шпаргалка показывает оба варианта. Профиль-переключатель хуже: его надо найти, он ломает поддержку («какой у вас режим?») и ничего не даёт сверх алиасов.

**Алиасить только действия с паритетом:** E reply, F improve, G greeting, D ping, V review, O tone, X cancel. H — только с честной подписью (в расширении это маршрут в Coach). S, C, L, M не алиасить: recap picker, Coach, Split и открытие Spenders в desktop-keymap отсутствуют; S в desktop = Scan, это другая функция.

**Сравнение с Alt+1..5 в обоих клиентах**
- Мышечная память: цифры обнуляют её у всех текущих пользователей обоих клиентов; алиасы — ни у кого.
- RU/EN: единственный плюс цифр (раскладка не меняет символ). Но то же даёт переход на `event.code` для букв, дешевле и без миграции.
- Alt+Shift и смена языка: риск одинаков для обоих вариантов — расширение уже сидит на Alt+Shift, а Alt+цифры на Windows тоже под Alt. Цифры проблему не снимают.
- Паритет: 5 цифр < 7–12 действий, без мнемоники; в desktop Ctrl+1..9 уже «прыжок к чату», Alt+цифры создадут два смысла у одной цифры. На Linux Firefox Alt+1..9 — переключение вкладок (по брифу). На macOS Option+цифра/буква печатает спецсимвол (допущение из общих знаний, не проверено), поэтому «единая» схема всё равно расходится по платформам.
- Итог: цифровая схема сейчас не стоит миграции.

**Правки, видимые в исходниках**
1. `lib/keymap.ts` desktop: гейт редактируемых полей пропускает только `mod`/Escape; для Alt-алиасов нужно добавить `parsed.alt`, как уже сделано в `shared/keymap.ts` расширения.
2. Оба движка сравнивают `event.key`; для буквенных биндингов перейти на `event.code` (KeyE и т.д.), иначе в русской раскладке ни Ctrl+R, ни Alt+Shift+E не совпадут. Метки остаются латинскими.
3. `main/index.ts:417` — `{ role: 'editMenu' }`. Допущение: на macOS этот role включает Paste and Match Style на ⇧⌘V, а акселераторы меню срабатывают раньше renderer (комментарий там же). Тогда алиас V для review конфликтует; либо переопределить пункт, либо не алиасить V.
4. Метки захардкожены в ~19 файлах renderer; алиасы можно показывать только в шпаргалке/тултипах, не трогая кнопки.

**Живые проверки (минимум)**
- Windows RU/EN, стандартный Left Alt+Shift: переключает ли Alt+Shift+E язык в Firefox и в Electron, доходит ли keydown с `code=KeyE`.
- macOS Electron: перехватывается ли ⇧⌘V/⇧⌘H до keymap.
- Firefox Windows: Alt+Shift+буква не открывает меню.

Если первая проверка покажет смену языка — ломается уже текущая схема расширения, и тогда обоим клиентам нужен другой модификатор (кандидат Ctrl+Alt, с оговоркой про AltGr), а не цифры.

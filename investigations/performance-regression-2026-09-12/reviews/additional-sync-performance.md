## 3. [P2, условный дефект] Потеря lease не запрещает следующие физические retry attempts уже начатого logical request

**Место:** [executor.ts:640–657](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/executor.ts:640), граница HTTP attempts — [http-request.ts:65–86](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/shared/src/http-request.ts:65).

**Достижимая цепочка:** `executeNextSyncPageChunk` создаёт `leaseHeartbeat`; если heartbeat возвращает false/ошибку, меняется только локальный `leaseFenced`. Пока `executeStreamChunk` awaited, флаг не передаётся в handler/adapter; он проверяется после возврата ([executor.ts:661–675](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/executor.ts:661)). Например, Fansly DM conversations перед logical `getMessagingGroupsPage` проверяет `assertOwnedPageSyncLease` один раз ([fansly-dm-conversations.ts:422–429](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/fansly-dm-conversations.ts:422)).

Далее shared rate-limit waiter может ждать после reservation без cancellation/ownership recheck ([rate-limiter.ts:49–60](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/rate-limiter.ts:49)). Адаптер допускает по умолчанию 3 retry, то есть до 4 физических попыток ([adapter.ts:1993–2007](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/fansly/src/adapter.ts:1993)); `429/500/502/503/504` при допустимом Retry-After запускают очередную попытку ([adapter.ts:2105–2120](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/fansly/src/adapter.ts:2105)). Общий loop после retry delay снова вызывает waiter и `execute`, без lease/abort проверки ([http-request.ts:102–104,129–132](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/shared/src/http-request.ts:102)). Fetch имеет только собственный timeout signal ([adapter.ts:2008–2014](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/fansly/src/adapter.ts:2008)).

`started` observer этот пробел не закрывает: handler передаёт telemetry + `SyncChunkBudget` ([fansly-dm-conversations.ts:260–266](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/fansly-dm-conversations.ts:260)); budget только увеличивает счётчик ([chunk-budget.ts:14–18](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/chunk-budget.ts:14)); telemetry пишет attempt, а ошибки observers поглощает как warnings ([observability.ts:751–803](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/observability.ts:751)).

**Trigger:** оператор pause приходит после успешной ownership-проверки и во время rate wait, HTTP attempt либо retry delay. `pauseSyncBlock` доступен через admin control ([sync-blocks.ts:470–479](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync-blocks.ts:470)); `pausePageSync` ставит paused и обнуляет lease token/expiry ([page-sync.ts:2845–2881](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/db/src/repositories/page-sync.ts:2845)). Когда lease heartbeat уже обнаружил потерю, незаконченный request loop всё равно может начать следующий physical request; при подходящих retryable responses — более одного. Это касается именно **старта новых attempts после fence**, а не требования немедленно выбросить уже полученный ответ.

**Последствие и граница уверенности:** новые network attempts расходуют provider/egress budget, делают telemetry DB writes, а успешный ответ может быть captured и затем не применён: business page write защищён `withOwnedPageSyncTransaction` ([fansly-dm-conversations.ts:933](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/apps/runtime/src/services/sync/fansly-dm-conversations.ts:933), проверка до и перед commit — [sync-context.ts:106–111](/Users/dmitriy/code/goose/.worktrees/hub-regression-audit-20260912/packages/db/src/repositories/sync-context.ts:106)). При resume новый владелец повторит работу от непродвинутого checkpoint. По коду новое physical execution после fence достижимо; runtime pause+retry fixture не выполнялся и наличие таких событий в production не установлено. Ошибки записи под чужим lease или бесконечные retry **не** заявляются; loop bounded.

**Исправление:** передавать отмену chunk/request и проверять её на границе **каждой** physical attempt после rate wait и перед fetch; retry delay/waiter тоже должны завершаться по отмене. Loss-of-lease должно прекращать retry как отдельный terminal control outcome, не превращаться в transport retry. Сохранить raw capture для уже завершённого in-flight ответа и действующее transaction fencing. Для проверки исправления достаточно локального теста pause/fence во время waiter и retry delay с подсчётом последующих fetch; production не нужен.

Не подтверждены новые бессмысленные full sweeps или бесконечные immediate retries. Новый requestSeq намеренно может снять старый retry; provider Retry-After учитывается поверх backoff. Missed cadence slots не исполняются все подряд: scheduler считает текущий slot. 45s wall budget — admission на логической границе, не принудительный deadline уже начатого HTTP; само по себе превышение 45s не считается дефектом. Global state rows в status могут быть нужны для active sibling/group contention, поэтому их простое page-only ограничение не предлагается без сохранения этой информации.

Практический порядок: сначала убрать отброшенный COUNT (самая узкая проверенная лишняя работа), затем сузить preview read scope; cancellation при lease loss — отдельная условная корректность, требующая targeted local test. Размер экономии CPU/DB latency/network для production пока не измерен.

# Вход, общая навигация и управление возможностями

Продолжение исследования 11 сентября; подробная проверка и правки завершались 12 сентября 2026 МСК. База этого прохода — `2f55b035`. Проверка исходников и контрактов, без изменения production.

## Вход — `/login`

**Оставить.** Это доступ к рабочим данным; менять способ авторизации в рамках упрощения страниц не требуется. Основной сценарий: войти и попасть в ранее открытую страницу.

Подтверждено: ошибка входа существовала только как временный toast; форма шириной 380 px без внешних отступов плохо помещалась на узком экране; поля не помогали менеджеру паролей; просроченная сессия теряла исходную ссылку; ProtectedLayout отправлял на login при любой сетевой ошибке проверки сессии.

Исправлено: русские поля и постоянная ошибка возле формы, autocomplete, ограничение ширины с отступами, блок повторной отправки и ввода во время запроса. Сетевая ошибка проверки входа имеет собственный экран восстановления; 401 по-прежнему означает необходимость входа. Без подтверждённой сессии каталог не запрашивается. Возврат сохраняет path/query/hash, запрещает внешние адреса и возврат на сам login.

Ограничение: реальный логин/выход не выполнялись в production. Клиентский отказ в доступе не заменяет серверную авторизацию. Как и раньше, ошибка повторной проверки сессии размонтирует защищённый экран; его локальный черновик не переживает этот случай. У auth-query нет polling или обновления при фокусе, но явная invalidation может вызвать такой сценарий. Сохранение черновиков через повторный вход требует отдельного решения с учётом секретных полей.

Источники: `pages/LoginPage.tsx`, `components/layout/ProtectedLayout.tsx`, `api/auth.ts`, `api/sdk.ts`; контракт `me`/`login` в `packages/contracts/src/routes.ts`. Здесь и ниже короткие frontend-пути относительно `apps/dashboard/src/`.

## Возможности — `/settings?tab=features`

**Оставить как точку выбора.** Основной сценарий: найти возможность, понять последствия, перейти к её настройкам. 32 группы и 90 связанных ключей сопоставлены с реестром; назначение каждой группы и ограничения сохранены в [INVENTORY.md](INVENTORY.md).

При подробном проходе обнаружено: поиск по названию конкретного AI-инструмента не находил общую карточку; возврат из настройки терял поиск; изменение лимита могло ожидать применения, пока карточка показывала только состояние главного флага; проблемы базовых функций отсутствовали в стартовом списке дополнений.

Исправлено: поиск по назначению, ограничениям и ключам без поиска по секретным значениям; сохранение поиска/фильтра/выбранной карточки при переходе туда и обратно; pending любого связанного параметра; отдельный список «Нужно проверить», появляющийся при pending/unknown, включая базовые функции.

Loading, первичная ошибка, ошибка обновления со старым срезом, пустой поиск, отсутствие ключей в версии сервера, неизвестные значения, выключенное состояние и ожидание применения различаются. Включённая конфигурация не названа доказанной пользой или успешным выполнением.

Ограничение: рекомендации по использованию основаны на коде и датированном исследовании. Для необязательных сборщиков нет измеренного эффекта на работу или продажи; карточки этого не обещают. Отдельных выключателей кнопок AI в текущем API нет.

Источники: `pages/settings/FeaturesTab.tsx`, `featureCatalog.ts`, `featuresView.ts`, `configurationChoices.ts`; `packages/shared/src/config-registry.ts`.

## Работа Hub — `/settings?tab=configuration`, включая 32 перехода по `feature`

**Оставить полный технический список и настройку одной возможности.** Основной сценарий: проверить применённое значение, изменить один параметр, дождаться подтверждения. Общие параметры остаются общими; например, список доходов и покупок меняет оба сборщика.

Сохранены: полный map зависимостей staged-флагов, серверные running/desired состояния, optimistic version, черновик при polling, квитанция записи при failed refresh и явное согласие на сброс к окружению. Не заменены пустые allowlist разных типов одним общим смыслом; CAS по-прежнему использует ID и `*`.

Дополнительно исправлены возврат к конкретному поиску возможностей и доступное обозначение невалидного режима. Боковой переход в другой раздел очищает принадлежащий карточке поиск, чтобы он не оказался фильтром чужой страницы.

Ограничения: `boot` не становится live из-за появления новой формы; 77 серверных/read-only параметров не получают несуществующей записи через API. Применение на реальном fleet в этом проходе не проверялось.

Источники: `pages/settings/ConfigurationTab.tsx`, `ConfigurationEditors.tsx`, `ConfigChoiceField.tsx`; `services/app-config-service.ts` и `services/staged-config.ts` относительно `apps/runtime/src/`.

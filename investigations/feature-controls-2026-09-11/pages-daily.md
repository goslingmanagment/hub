# Ежедневные страницы Hub: разбор и локальная доработка

Дата разбора: 12 сентября 2026, Москва. Основа: `codex/feature-controls-20260911` после `2f55b035`. Область: **10 из 10 назначенных страниц** и принадлежащие им компоненты. Исследованы исходники, контракты SDK и запросы данных; production и браузер этим агентом не изменялись и не проверялись.

## Решение по составу

| Страница | Для кого и зачем | Решение |
|---|---|---|
| Overview | Владелец / тимлид: оценить изменение дохода, найти страницу и провалиться в операции | Оставить основным входом; сохранить выбранную компактную композицию |
| Transactions | Владелец / тимлид: объяснить точную сумму из Overview | Оставить как точную детализацию, доступную из суммы |
| PageDetail | Работа с одной страницей: доход, аудитория, спендеры, состояние сбора | Оставить; показывать сбои отдельных блоков независимо |
| SpenderAutoList | Найти фанов в конкретном диапазоне gross spend | Оставить вторичным списком; не смешивать диапазон gross с creator net |
| DeletedFans | Разобраться с исчезнувшим аккаунтом и его прежними именами | Оставить аудитом; не продвигать в ежедневную рабочую очередь |
| Subscribers | Проверить текущий доступ, известное истечение и отключённое продление | Оставить отдельным рабочим сценарием |
| Followers | Найти аудиторию по имени, истории алиасов, записанному диалогу и активности | Оставить; объяснять пределы сигналов |
| FanProfile | Проверить фана: доход, подписка, досье, заметки, операции | Оставить; не подменять недоступные блоки нулём или отсутствием |
| TopSupporters | Выбрать приоритетных фанов по доходу и сигналам общения | Оставить; подсказки Next считать эвристикой, состояние данных показывать явно |
| WorkboardV2 | Последовательно разбирать приоритетную очередь и внутренние отметки | Оставить доступным, дальнейшее расширение отложить до подтверждения рабочего сценария; отдельное направление workboard уже зафиксировано в Decision 119 |

Отсутствие измерений посещаемости не доказывает бесполезность этих страниц. Для их открытия используются существующие SDK-операции Hub; закрытие страницы не равно отключению сборщика данных. В этом изменении ни один сборщик, флаг или исторический факт не отключён и не удалён.

## 1. OverviewPage

**Сценарий.** Выбрать период → найти изменение внутри модели → раскрыть источники → открыть операции конкретной суммы. Группы моделей сортируются по серверному доходу; аудитория разных страниц не складывается.

**Оставить.** Текущую таблицу, предыдущие окна, дельты, отрицательные корректировки, архивные строки, раскрытие источников, график выбранной области. Это различимые задачи, а не повод отключать сбор.

**Подтверждено.** Основной ответ, каталог, источники и графики читаются независимо. `windowAt` фиксирует календарную границу, но не общий снимок БД и не время последнего захвата. Overview уже отличает failed refresh от первичной ошибки, не показывает placeholder прошлого периода под новым, хранит раскрытие/сортировку/период/график в URL и восстанавливает scroll/focus.

**Исправлено.** Обе ссылки на PageDetail теперь передают явный `period`. До этого переход из Overview с периодом в URL мог открыть страницу с другим периодом из persisted store. Композиция, запросы, расчёты, сортировка и денежные ссылки сохранены.

**Ограничения.** Полнота платформенной истории не доказана. Разные блоки могут иметь разное время чтения, несмотря на одинаковую календарную границу. Живой мобильный/визуальный прогон не выполнен; responsive-колонки и source-cell colspan проверены только по коду.

**Источники:** `apps/dashboard/src/pages/OverviewPage.tsx`, `pages/overview/{PageSources,RevenueCharts,presentation}.tsx/.ts`, `docs/decisions.md` Decisions 291–292.

## 2. TransactionsPage

**Сценарий.** Из суммы Overview открыть `[from,to)` и сверить итог всего фильтра с постраничным списком. Менять источник/статус, затем вернуться к той же области Overview.

**Оставить.** Общую сумму по всему фильтру, число операций, применённые границы UTC, тип/статус, ID операции и страницы, пагинацию. ID полезен для сверки, но остаётся вторичным текстом.

**Подтверждено.** Запрос строится через строгий parser; неполное окно не посылается. Ответ без подтверждения scope или с несовпадающим scope не используется для сверки. Count, итог и список возвращаются из одной транзакции чтения. Смена фильтра сбрасывает offset; backTo проходит safe-path проверку.

**Исправлено.** Статусы переведены в понятные подписи «Ожидает подтверждения», «Проведена», «Неизвестен». Значения wire enum и фильтры сохранены.

**Состояния/узкие экраны.** Есть loading, отдельный QueryNotice с ручным повтором, stale-данные и объяснение несовместимого сервера. Таблица прокручивается горизонтально; пустой offset отличён от отсутствия записей во всём фильтре.

**Ограничения.** После нового чтения итог может измениться из-за новых данных. Это net после комиссии платформы, включая pending/корректировки согласно фильтру, а не прибыль агентства или сумма к выплате.

**Источники:** `pages/TransactionsPage.tsx`, `lib/{transactionNavigation,overviewNavigation,revenueDisplay}.ts`, `api/transactions.ts`, Decision 292.

## 3. PageDetailPage

**Сценарий.** Открыть страницу → проверить её доход и состояние данных → выбрать подписчика/спендера → открыть профиль → вернуться к той же вкладке и позиции.

**Проблемы.** Вторичные запросы отдавали только `data`; отсутствие ответа превращалось в «0 total», «No subscribers», «No transactions» или пустые графики. Заголовок транзакций не сообщал, что глобальный период не ограничивает этот список. Вкладка и offsets пропадали после профиля. Название New Subscribers могло читаться как привлечение новых людей, хотя источник — текущие изменяемые записи подписок. Таблицы внутри `overflow-hidden` обрезались.

**Исправлено.**

- Доход, графики, подписчики, авто-списки, операции и спендеры получили независимую границу чтения `daily/ReadSection`: loading/первичная ошибка/stale различаются; доступные данные сохраняются, повтор — вручную.
- Sync-сводка теперь отдельно читается через `useOverview` и сопоставляется с metadata-каталогом по id. Недоступность sync не блокирует доход и аудиторию. Политика скрытия credential-исключения на этом уровне сохранена; неизвестный sync не становится healthy.
- `tab`, `type`, `txOffset`, `spendersOffset`, `period` читаются из URL. Смена типа явно сбрасывает `txOffset`. Browser Back и повторное открытие URL не сбрасывают позицию эффектом монтирования.
- Ссылки на авто-списки и профиль несут выбранный период; профиль получает полный маршрут возврата.
- Пояснения называют creator net, пределы захвата и отдельный смысл списка всех операций. Аудиторный график описывает записи о начале подписок, а не прирост уникальных людей.
- Таблицы прокручиваются; в строках подписчиков/спендеров есть клавиатурно доступная кнопка профиля. Будущая дата больше не получает бейдж NEW. Отсутствующие window metrics дают прочерк.

**Оставить/упростить дальше.** Оставить центральные блоки; авто-списки и графики являются вторичной детализацией. Автоматически скрывать их без данных об использовании не следует. Если понадобится компактный режим, первыми сворачивать графики/списки, сохраняя быстрый доступ и явное состояние загрузки.

**Ограничения.** Транзакции внутри PageDetail по-прежнему показывают всю сохранённую историю. Это теперь объяснено; для точной суммы за окно остаётся Transactions. Сбор не управляется отсюда — существующая ссылка ведёт в Settings → Sync. Общую замену тяжёлого каталога shell на `usePages()` выполняет основной агент отдельно.

**Источники:** `pages/PageDetailPage.tsx`, `api/pages.ts`, `pages/daily/ReadSection.tsx`, `packages/contracts/src/routes.ts` subscriber/follower/spender schemas, `packages/db/src/repositories/reporting.ts`, Decisions 166, 171, 291–292.

## 4. SpenderAutoListPage

**Сценарий.** Из выбранного диапазона расходов открыть список → при необходимости оставить followers → найти фана → проверить профиль → вернуться к списку.

**Оставить.** Диапазон gross spend, отдельную колонку creator net, статус follow/subscription, последнюю операцию, поиск, пагинацию. Gross определяет диапазон, net показывает доход создателя: их нельзя объединить под одним безымянным «Spent».

**Исправлено.** Поиск, followersOnly и offset теперь живут в URL; изменение поиска/условия сбрасывает offset в том же действии. Период из URL согласован с общим селектором. Полный возвратный маршрут и период доходят до FanProfile. Вместо только клика по строке добавлена настоящая ссылка профиля. Есть retry первичной ошибки и предупреждение stale; таблица больше не обрезается на узком экране.

**Пустые состояния.** При пустом offset>0 показано «эта страница списка пуста» и действие «К началу списка». Заголовок не выдаёт 0 из такого ответа за достоверную численность всего сегмента.

**Ограничения.** Живого показателя использования сегментов и эффекта контактов нет. Это derived read по данным Hub, а не отдельный переключатель сбора. API с count-over-window не всегда знает общий total за пределами последней страницы.

**Источники:** `pages/SpenderAutoListPage.tsx`, `api/pages.ts` usePageSpenderAutoList, `packages/contracts/src/routes.ts` pageSpenderAutoListDetailResponse, `packages/db/src/repositories/spenders.ts` listPageFansByLifetimeGrossBucket и period bucket path.

## 5. DeletedFansPage

**Сценарий.** По зафиксированному удалению посмотреть ID, последнее имя/алиасы и даты обнаружения; использовать как объяснение исчезнувшего аккаунта.

**Оставить вторичным аудитом.** Удаление аккаунта не отменяет исторические деньги. Убирать этот аудит или удалять его строки из-за низкой частоты открытия нельзя. На постоянную рабочую панель его выносить не требуется.

**Исправлено.** Пагинация сохраняется в URL. Есть повтор первичной ошибки и stale-предупреждение; широкая таблица доступна через горизонтальную прокрутку. Пояснено различие обнаружения удаления и точного времени удаления. Пустой поздний offset не объявляется «удалённых фанов нет»; есть возврат к началу.

**Ограничения.** Серверного поиска в контракте нет; не добавлен ложный поиск только по 50 видимым строкам. Дата последнего подтверждения может быть неизвестна. Исторические имена имеют отдельную ценность для сопоставления; упрощать до одного текущего username нельзя.

**Источники:** `pages/DeletedFansPage.tsx`, `api/pages.ts` usePageDeletedFans, `packages/contracts/src/routes.ts` pageDeletedFansResponse, `packages/db/src/repositories/reporting.ts` listDeletedFansForPage, Decision 193 (сохранение удалённых в отдельном top-spenders контракте не означает одинаковую выборку всех UI).

## 6. SubscribersPage

**Сценарий.** Открыть текущих подписчиков → истечение ≤7 дней / начало ≤24 часов / явно выключенное продление → найти фана → профиль → возврат.

**Оставить отдельной страницей.** Статусы доступа, даты окончания и auto-renew дают рабочий сценарий, отличающийся от общего списка followers и ранжирования денег. Не считать всех платящими и не суммировать аудиторию разных страниц.

**Подтверждено.** URL уже сохраняет filter/query/offset и полный backTo профиля. Поиск действует на таблицу; четыре счётчика категорий получаются отдельными запросами без поиска. Nullable autoRenew не попадает в «выключено»; неизвестная дата окончания не входит в expiration group. Сбой главного чтения и stale показаны отдельно; таблица прокручивается.

**Исправлено.** Будущая дата начала больше не получает бейдж NEW. При пустом позднем offset UI предлагает начало списка, не объявляя отсутствие подписчиков в фильтре.

**Ограничения.** Фильтр New24h означает sourceCreatedAt текущих записей, не доказанный прирост. Backend имеет нижнюю границу, но не верхнюю проверку будущих дат; UI исправляет бейдж, не переписывает бизнес-выборку. Счётчики категорий читаются отдельно и могут относиться к разным моментам; их ошибки пока не имеют отдельного локального retry-блока. Полная локализация текущего смешанного языка — отдельная согласованная задача всего Hub.

**Источники:** `pages/SubscribersPage.tsx`, `lib/overviewNavigation.ts`, `api/pages.ts` usePageSubscribers, `packages/db/src/repositories/reporting.ts` listSubscribersForPage, Decision 292.

## 7. FollowersPage

**Сценарий.** Найти фолловера по текущему/историческому имени или ID, проверить сохранённый DM и сигнал активности, открыть профиль с возвратом.

**Оставить.** All/New24h/Unmessaged/Active/Subscribers — разные фильтры по текущей записи, а не независимые наборы фактов. Счётчик описывает выбранный фильтр.

**Исправлено.** Filter/query/offset перенесены в URL; смена условия сбрасывает offset, а Back восстанавливает его. FanProfile получает полный возвратный путь. Ошибка refresh отмечена поверх сохранённых строк; у первичной ошибки появился retry. «No DM yet» заменено на «Нет записанного диалога»: отсутствие записи не доказывает, что переписки никогда не было. Пояснён Active = сохранённый сигнал за 120 минут. Будущие даты не маркируются NEW. Пустой поздний offset имеет возврат к началу.

**Узкие экраны.** Существующая широкая таблица с прокруткой сохранена: спрятать DM/подписку без альтернативы означало бы убрать основную причину открытия. Профиль — настоящая ссылка, доступная с клавиатуры.

**Ограничения.** Presence является последним сохранённым сигналом; label Active now на сервере допускает окно 30 минут и не доказывает онлайн сейчас. Старый API без enrichment честно блокирует соответствующие фильтры при наличии старых строк; пустой ответ старого сервера сам по себе не позволяет проверить поддержку новых полей. API не возвращает отдельного доказательства полной платформенной аудитории.

**Источники:** `pages/FollowersPage.tsx`, `packages/contracts/src/routes.ts` followerItem/list schemas, `packages/db/src/repositories/reporting.ts` listFollowersForPage.

## 8. FanProfilePage

**Сценарий.** Проверить конкретного фана на конкретной странице: доход за окно, текущую подписку, досье/его версии, заметки, последние операции и всю историю.

**Оставить.** Персона на странице и её история имеют отдельную ценность. Досье с историей версий нельзя без измерений убрать как «редкую функцию»; сбор досье и допуск его в AI prompt управляются отдельно. Заметки остаются append-only через существующий API.

**Проблемы.** Независимые failed/loading reads денег/истории/досье превращались в $0, «No activity» и «No profile». Четыре колонки метрик и две колонки активности были фиксированы на телефоне. Успешное сохранение заметки могло стереть текст, набранный во время запроса, или черновик после перехода на другого фана.

**Исправлено.**

- Деньги, последние операции, история операций и выбранная версия досье различают loading/error/stale. Ошибка истории версий не говорит «нет версий». Отсутствующие window metrics остаются прочерком.
- Метрики объяснены как creator net на этой странице; история — все периоды, Timeline — последние 10 операций, а не вся активность.
- URL период совпадает с видимым селектором и сохраняется при входе из денежных списков.
- Заметка очищается после успеха только для того же routeKey и того же отправленного текста. Повторный submit во время pending не допускается. Ошибка не очищает черновик; автоматического повтора записи нет.
- Метрики адаптируются 2→4 колонки, заметки/операции 1→2; таблица истории прокручивается. Textarea получила доступное имя. Первичная ошибка профиля даёт retry и возврат к списку.

**Ограничения.** Содержимое досье является сохранённым документом, не независимой проверкой каждого утверждения. Вкладка версии и txOffset пока локальные: при новом открытии профиля начинается актуальная версия и первая страница. Черновик заметки не переживает уход со страницы/перезагрузку; добавлено только сохранение при завершении конкурирующего запроса, не новая система автосохранения.

**Источники:** `pages/FanProfilePage.tsx`, `api/pages.ts` profile/version/transactions/note hooks, `packages/contracts/src/routes.ts` fan detail/document schemas, Decisions 31, 136, 177.

## 9. TopSupportersPage

**Сценарий.** По выбранному периоду/сегменту найти приоритетного спендера, сравнить расходы, проверить последнее общение/операцию, открыть профиль.

**Оставить.** Ранжирование net, retention-сегменты, подписку, подсказку Next, последнюю операцию, быстрые previews. Удалять редкие previews до проверки сценария не предлагается. Лейблы VIP/Whale основаны на локальных порогах lifetime net, не доказывают будущую выручку.

**Исправлено.** Первичная ошибка больше не оставляет бесконечный skeleton. Failed refresh и ошибка batch enrichment видимы отдельно. Неполный batch не показывает суммарную разбивку расходов как будто все строки покрыты, а неизвестная подписка не превращается в отсутствие. Null window metric не подменяется нулём. Offset валидируется как safe nonnegative integer. Профиль получил настоящую ссылку, полный backTo и период. Эффект, обнулявший offset при каждом повторном монтировании, удалён; previews сбрасываются при смене страницы. Пустой поздний offset отличён от пустого сегмента.

**Пределы советов.** Next вычисляется локально: ближайшее истечение, retention, последнее сообщение, cooling. Это эвристика по сохранённым фактам; отправки сообщений не выполняет. Добавлено соответствующее пояснение. F/M времена и «неотвечено» не являются доказательством полного захвата переписки.

**Ограничения.** Сортировка/фильтр/search сохраняются в URL, но period при отсутствии параметра использует отдельный исторический `topSupportersPeriod`. Previews открываются кликом по ячейке и требуют отдельной проверки клавиатуры; основная ссылка профиля теперь доступна. Общие preview-компоненты вне области этого агента. Имена полей Spent здесь означают net, в auto-list диапазоны означают gross; пояснения сохраняют различие.

**Источники:** `pages/TopSupportersPage.tsx`, `api/pages.ts` useSpenders/useSpenderBatch, `packages/db/src/repositories/spenders.ts` buildRetentionFilterSql/listRankedSpenders, `packages/contracts/src/routes.ts` spender list/batch schemas.

## 10. WorkboardV2Page

**Сценарий.** Выбрать рабочую очередь или gross-spend bands → проверить why-now/контекст → поставить внутреннюю отметку «Готово» или отложить. Эти кнопки не отправляют сообщение фану.

**Оставить/ограничить развитие.** Оставить доступ и существующий priority engine. Не превращать этот экран в ещё один обязательный основной центр поверх TopSupporters: Decision 119 сохраняет отдельный standalone workboard как направление. Для решения об отключении самого движка сначала нужны фактические handled/snooze события и рабочий владелец очереди.

**Проблемы.** Ошибка фонового чтения скрывалась. После recompute/смены списка старый focusedFanId мог остаться и получить действие e/s. Обработчик клавиш срабатывал на интерактивных элементах и повторе клавиши. Ошибка записи кратко исчезала в toast, не оставляя понятного следующего действия. localStorage исключение могло уронить страницу.

**Исправлено.**

- Failed refresh явно помечен; старые строки остаются видимы. Первичная ошибка не объявляет конец очереди. Внутренние отметки недоступны при ошибке/обновлении чтения и pending записи.
- Shortcut resolver использует текущие видимые fanId; скрытые bands и исчезнувший focus не авторизуют действие. Игнорируются ввод, кнопки/ссылки/select/dialog, Ctrl/Alt/Meta и повтор записывающей клавиши. Навигация и просмотр доступны, когда записи временно закрыты.
- Синхронный in-flight guard дополняет mutation pending, предотвращая повтор до следующего React render. Неподтверждённая запись остаётся постоянным предупреждением: могла сохраниться, сначала обновить и проверить исходную очередь. Предупреждение связано с pageLabel: чтение другой страницы его не снимает, переход обратно доступен по ссылке. Автоповтора нет.
- Финальная независимая проверка обнаружила, что старый toast «Отменить» после перехода A→B мог вызвать mutation observer уже с pageLabel B для фана A. Исправлено: toast хранит исходные pageLabel/fanId/тип отметки; перед отменой проверяются живой компонент, актуальная страница, pending/unknown и состояние чтения. При несовпадении страницы запись не вызывается, причина видима. Undo pending блокирует новые отметки. Успех отмены подтверждается явно; ошибка оставляет постоянное предупреждение и toast с исходной страницей, без автоматического повтора. Клик по отказанной/неподтверждённой отмене не закрывает исходное уведомление автоматически. Исчезновение обработанного фана из очереди само по себе не запрещает отмену подтверждённой отметки.
- Snooze использует тот же disabled-state; disclosure-кнопки получили aria-expanded. Заголовок переносится на узком экране; недоступный localStorage не блокирует работу.
- Ошибка чтения переписки в принадлежащей Workboard строке отмечена отдельно; отсутствие сохранённых сообщений не называется доказанным отсутствием переписки.

**Ограничения.** Пагинация очереди — 100 строк; counts отражают весь backlog, а заголовки status-секций — текущую страницу. В lists mode сервер может truncate bands; UI это сообщает, полного обхода такого списка нет. Hover-preview переписки требует отдельного полноценного решения для touch/клавиатуры. Tab/offset Workboard пока не перенесены в URL. Проблема непроверенного результата внутренних отметок обозначается, но отдельной durable receipt/command id в этом контракте нет.

**Источники:** `pages/WorkboardV2Page.tsx`, `components/page/workboard/v2/WorkboardV2Row.tsx`, `pages/daily/workboardKeyboard.ts`, `api/workboard.ts`, `packages/contracts/src/routes.ts` workboardV2 response/mutations, `packages/db/src/repositories/workboard-v2.ts`, Decisions 94, 117, 119.

## Проверка и остаток

Новые содержательные проверки: `tests/dashboard-daily-page-review.test.ts` — независимые состояния чтения, отсутствие ложных $0/empty при сбоях, сохранённые route context/периоды/offset, недоступный batch, ограждения Workboard при обновлении/скрытых строках/клавиатуре. Полный прогон централизован у основного агента, параллельные suites этим агентом не запускались. Локально parser TypeScript проверил изменённые TS/TSX без синтаксических ошибок; это не заменяет typecheck, unit tests или визуальную проверку.

Непроверенные пределы: реальные browser Back/forward и смена period в Topbar; короткий экран с таблицами и раскрытым досье; touch/клавиатура и действия Workboard в живом браузере. Текущая фаза покрывает code/SSR/контракты и централизованную сборку; локальный preview монтирует только Settings. Результат общего `pnpm check` фиксирует основной агент. Нет данных, позволяющих честно оценить ROI всех страниц, и нет основания отключать capture только ради сокращения интерфейса. Отдельные backend-ограничения total при пустом offset, доказательства охвата и будущих relationship timestamps зафиксированы выше, но не менялись в UI-проходе.
